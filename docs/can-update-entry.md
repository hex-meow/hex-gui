# 统一 CAN 固件升级入口

CAN 页面统一处理 HPM V3、STM32 CANopen DFU 和 Motor IAP。默认只监听标准 Classic CAN 心跳，再对候选 Node-ID 严格读取 `0x1018:00..04`；不扫 LSS、不发 IAP、不对未知设备试写。完整身份匹配本地已启用产品后才能选中。文件、厂家名称或网络 metadata 都不能启用未知型号。

## 正常升级

1. 选择接口，默认已验证的 Classic CAN 1 Mbit/s。
2. 点击发现；候选来自心跳，身份读取失败、未知型号、未配置身份和保留 ID 均明确显示并禁用。
3. 选中已知设备，由本地产品表选择对应后端。
4. STM32／Motor IAP 保留各自身份绑定的在线发布和严格本地文件路径；HPM V3 使用签名 `.hpmota/3`，选择后通过原生发现快照捕获。
5. 写入前重新核对身份。HPM 在新连接上先读完整 1018，与发现快照逐字段比较，再检查 INFO 的产品与 UID-hash serial；通过后才 CLAIM。

HPM 当前登记 `6865786D/45564B33`（HPM5300EVK）。IMU 产品编码、公钥／BSP 完成后才添加正式产品。HPM 的 CLAIM 后 RAM 锁存、无周期保活、RELEASE 不自动启动逻辑保持。USB 入口仍支持精确 0100→gcan legacy profile 和独立 V3 signed package。

## 故障恢复

普通发现旁边只有一个“故障恢复”按钮。进入后先查看 HPM／STM32／Motor IAP 的图片和说明，再选择本地登记的准确型号，并点击确认。确认前只读取本地型号列表，不操作 CAN。图片仅帮助识别；STM32 图片是标注过的控制板示意图，电机照片为 HEX-4310，实际型号仍以选择框与实物为准。

- **HPM**：确认型号后才授权恢复捕获；已有 ID 时核对 1018，无 ID 时可显式 LSS Configure／Store，随后 SDO INFO／CLAIM。分配地址由操作者确认空闲，禁止 100／101。
- **STM32**：提示先发现再复位，仍使用 BL 心跳与完整 1018；列表只能选所确认的型号，继续复用完整 meowpkg、身份、硬件和加密策略检查。
- **Motor IAP**：仅在确认型号后，主动扫描 Enter-IAP 并保持本次 CAN lease；扫描排除 Node-ID 100／101。选择匹配应答、校验 IMG 后调用主机库的 recover API，不从失效 APP 再发 Reset。开始写入前再次核对 IAP device／firmware 与所选策略和 IMG。原 CANopen serial 在这种恢复中无法读取，界面明确告知。

全 FF／损坏／型号不匹配的 IAP 身份只显示诊断，不允许写入。未资格验证的型号保持不可用。要求强制 `0x4001` 校准备份的 Meow Motor 型号不进入通用无身份恢复，以免绕过现有备份要求；需要有备份绑定与后续校准复核的专门恢复方案。这些限制不能通过手选文件取消。

恢复和正常升级互斥，一次执行一个任务。离开恢复会释放当前总线与文件授权，返回普通被动发现。取消按协议命令边界执行；命令已送达后的模糊结果不盲目重发。Verify／JUMP ACK 不等于 APP 已通过健康自检。

## 保留地址

**禁止使用 Node-ID 100（0x64）与 101（0x65）。** Motor IAP 发送 `0x780 + Node-ID`，分别撞上 LSS 的 `0x7E4/0x7E5`。

- Device Settings 与 Meow 通信设置在 UI／Rust 后端拒绝将新地址设为这两个值。
- Motor Control 立即显示错误，初始化、目标、模式、校准启动等原生操作也被拒绝；批量初始化逐节点返回错误。
- 正常 DFU 不授予这两个地址升级能力；HPM 捕获在总线 I/O 前拒绝，Motor IAP 恢复不探测这些地址。
- 允许在 Device Settings 将已有错误地址改回其他合法地址，避免禁止控制后失去修正途径。读身份／诊断不等于授予电机控制或升级能力。

## 验证边界

离线测试覆盖未知身份只产生五次标准 1018 read、身份变化零 mailbox／CLAIM、保留 ID 零总线操作、本地产品路由不重叠、恢复型号选择授权、校准备份门限保留。前端类型／构建／回归与 Chrome 中的模拟 Tauri 界面检查独立验证交互。实际型号恢复、不同适配器的无 ACK 硬件队列取消，以及 macOS／Windows 原机仍需对应硬件验收；软件 send timeout 不能证明硬件已停止重发。
